البداية السريعة

ثبّت النواة ومكتبات النظارات من المستودع المحلي، ثم افتح جلسة افتراضية. الانتقال إلى جهاز فعلي يحتاج استيفاء متطلبات مساره واختباره على العتاد؛ لم يُنفّذ هذا الاختبار بعد.

# من مجلد المشروع المحلي الخاص
pip install -e packages/metalife-core -e packages/metalife-solos \
            -e packages/metalife-halo -e packages/metalife-rayneo
# packages/metalife-moyoung غير مضمّن في مجموعة المصادر الأساسية (ملحق خاص بحقوق غير محسومة)
pip install fastapi 'uvicorn[standard]'
(cd apps/platform-api && uvicorn app.main:app --port 8791) &
# الموقع ووحدة التحكم: python -m http.server 8792 من apps/developer-platform

البنية

النواة metalife-core تعرّف: نموذج القدرات (17 قدرة)، حالات التحقق الأربع، ناقل الأحداث، عقد النقل (Transport)، وجهازاً افتراضياً حتمياً (VirtualGlasses). كل مكتبة نظارة تُصدر «ملف طراز» يصرّح بما تدعمه وبحالة كل قدرة، فلا يمكن لمسارٍ غير مُختبَر أن يظهر كأنه يعمل.

المكتبات الأربع

  • metalife-moyoung - يعكس CRPBleClient/CRPBleConnection من وثائق الشركة 1:1 بأسماء بايثون، مع ترميز protobuf حقيقي.
  • metalife-solos - سطح v5.9.2 الموثّق (صوت PCM، سماعة، كاميرا V2، RTMP، اتجاه الرأس - اتجاه فقط وليس تتبع نظرة).
  • metalife-halo - مبني على brilliant-sdk الرسمي (BSD 3-Clause) الذي يدعم Halo وFrame: رسائل BLE مباشرة (نص، التقاط، صوت، IMU، لمس).
  • metalife-rayneo - جسر مرافق TCP/NDJSON (بروتوكول v1.1 بمصادقة توكن) لوكيل على الجهاز مبني بـxg.glass (Apache-2.0)، بلا أي مكونات من الشركة في المسارات الأساسية.

بروتوكول MoYoung

مخطط التشغيل الحالي: ble_message.proto (38 رسالة) مشتق من SDK العميل 0.0.7 المُورَّد - مادة مشتقة بحقوق غير محسومة (انظر docs/DERIVED-MATERIAL.md)، لذا الملحق اختياري وللاستخدام الخاص. المخطط الموسّع (82 رسالة) من ملحق pub.dev العام: للبحث الداخلي فقط وحقوقه غير مُبرّأة. الغلاف الخارجي وعناوين GATT غير منشورة - طبقة framing.py موسومة «فرضية، غير مُختبَرة على عتاد» والكتابة على العتاد معطلة حتى التأكيد.

واجهة المنصة API

POST /v1/apps                      # تسجيل تطبيق → مفتاح mlfk_...
POST /v1/apps/rotate-key           # تدوير فوري (القديم يموت لحظياً)
GET  /v1/apps/me                   # إحصاءات التطبيق
POST /v1/sessions                  # جلسة (vendor؛ bridge_id اختياري للتوجيه العتادي)
GET  /v1/sessions                  # جلساتي · POST /v1/sessions/sweep للكنس
POST /v1/sessions/{id}/battery     # البطارية (افتراضي أو عبر الجسر)
POST /v1/sessions/{id}/photo       # التقاط صورة
POST /v1/sessions/{id}/display     # عرض نص
GET  /v1/sessions/{id}/events/ws   # بث أحداث لحظي (WebSocket، عزل 4401/4403)
POST /v1/bridges                   # اقتران وكيل (مصادقة فعلية قبل الحفظ)
GET  /v1/bridges                   # قائمة (بلا توكنات) · DELETE /v1/bridges/{id}
POST /v1/bridges/{id}/call/{method}
# method: ping|scan|connect|battery|take_photo|sync_time|display_text|record_audio
GET  /v1/models                    # مصفوفة القدرات كاملة

بروتوكول الجسر v1.1 (وكيل الجهاز)

قناة TCP بسطر JSON لكل رسالة (NDJSON) بين المنصة ووكيل النظارة. الإغلاق المُحكم افتراضياً: بلا توكن مُهيأ يرفض الوكيل كل اتصال. التوكن يُولَّد على الجهاز (24 بايت عشوائية آمنة) ويظهر على شاشة الوكيل فقط.

→ {"id":1,"method":"auth","params":{"token":"…"}}        # أول سطر إلزامياً
← {"id":1,"ok":true,"result":{"auth":true}}
→ {"id":2,"method":"battery","params":{}}
← {"id":2,"ok":true,"result":{"level":88}}

أمان المنصة: أهداف الجسر عناوين IP حرفية فقط (لا DNS)، loopback أو LAN خاص حصراً، link-local/multicast مرفوضة (بما فيها 169.254.169.254)، منافذ الوكيل المعروفة فقط (8765/8766)، ويُعاد التحقق عند كل استدعاء. التوكنات في الذاكرة فقط - لا قاعدة بيانات، لا سجلات، لا قوائم.

مصفوفة التحقق

المصدر التفصيلي في docs/COMPATIBILITY.md. القاعدة: «مُختبَر برمجياً» يعني على الناقل الافتراضي بحمولات البروتوكول الحقيقية حيث يعرف؛ «مُنفَّذ» يعني كود مسار حقيقي لم يُشغَّل على جهاز؛ «محظور» يعني وصول الشركة ناقص ومذكور الحل بالاسم.

التراخيص والحدود

الكود ملك لشركة OSH للتكنولوجيا والذكاء الاصطناعي (حقوق محفوظة). لا يُعاد توزيع أي ثنائي للشركات المصنّعة. مخطط MoYoung (38 رسالة) مادة مشتقة من SDK العميل بحقوق غير محسومة - استخدام خاص فقط حتى تُحسم الحقوق (docs/DERIVED-MATERIAL.md)؛ والمخطط الموسّع على pub.dev (GPL-3.0) للبحث الداخلي فقط. brilliant-sdk مرخّص BSD 3-Clause وxg.glass مرخّص Apache-2.0 مع الإسناد محفوظاً. ترخيص Solos يمنع الهندسة العكسية - لذلك يقف مساره عند الوثائق حتى الاشتراك الرسمي.
